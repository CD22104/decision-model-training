# Training RSI Skill：版本

## 1.0（`trsi` 1.0.0，2026-11-23）

第一个能在团队框架里直接用的版本：训练全部通过 onejev-harness，代码里不写任何具体任务。

- **能选的**：基座（模型选择）、配方（全参或 LoRA）、超参（`onejev.<flag>`、`lora.<字段>` 的 override，每项带原因）。范围由用户在运行配置里批准一次。
- **判输赢**：先跑种子 0，比当前方案同一种子高过 0.035 才补到 3 个种子；3 个种子平均高过 0.035、ECE 和 Brier 不明显变差才接受。门槛、种子数、护栏可配置。
- **预算**：按 harness 记录的卡时记账，可按卡型折算；失败的试验照记；超预算不再启动。
- **记录**：archive.jsonl、incumbent.yaml、report.md；同一方案同一种子只训练一次。
- **测试**：19 个，只用 CPU，用一个假的 `ojh` 跑完整流程。

还没有在真的 harness 上跑过一轮；第一轮会用 `experiments/elliptic_txhist/`。

### 依据：这之前在 Elliptic 上直接用 OneJev 试过的做法（v0）

v0 是一个自动循环：每轮先对很多选项做 400 步的短跑筛选，入围的直接跑 3 个种子的完整训练。在 Elliptic 交易历史输入上跑了 3 轮（约 287 A100 卡时），没有找到比团队配方更好的方案，并发现：

- 短跑筛选不可信（两次筛选的排名相关 0.08，筛选看好的 4 个完整训练都没赢），所以 1.0 不筛选，直接用种子 0 的完整训练当探针；
- 一轮 3 个种子太贵，而 3 个种子本来只看得出 0.035 以上的改进，所以先用 1 个种子把明显不行的挡掉；
- 判断者不在时规则表自己开新一轮，把卡花在先验很低的选项上，所以 1.0 的规则从不自己开新候选；
- 1/4 数据的小环境和完整训练排名对不上（0.09–0.37），所以 1.0 不提供替身环境。

细节见 `reference/protocol.md` 和 `reference/lessons.md`。
